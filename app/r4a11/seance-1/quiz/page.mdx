## React Native et Expo

<QuickCheck
  question="3. Que fait React Native avec un composant <View> ?"
  options={[
    "Il crée une balise <div> dans une WebView",
    "Il le traduit en composant natif de la plateforme (UIView sur iOS, android.view.View sur Android)",
    "Il le convertit en HTML standard",
    "Il l'envoie directement au navigateur"
  ]}
  correctAnswer={1}
  explanation="React Native traduit les composants JSX en composants natifs de chaque plateforme. <View> devient UIView sur iOS et android.view.View sur Android. Il n'y a pas de WebView ni de HTML : ce sont des composants natifs réels."
/>

<QuickCheck
  question="4. Quel est le rôle d'Expo Go ?"
  options={[

    "Un compilateur qui génère les fichiers .apk et .ipa",
    "Un framework CSS pour React Native"
  ]}
  correctAnswer={1}
  explanation="Expo Go est une application installée sur votre téléphone qui charge votre projet React Native via le réseau Wi-Fi. Vous scannez un QR code et l'application se charge instantanément, avec rechargement automatique à chaque modification du code (Fast Refresh)."
/>

## Composants primitifs

<QuickCheck
  question="6. Que se passe-t-il si vous écrivez du texte directement dans une <View> ?"
  options={[
    "Le texte s'affiche normalement",
    "React Native génère une erreur : le texte doit être dans un composant <Text>",
    "Le texte s'affiche mais sans style",
    "React Native convertit automatiquement le texte en composant <Text>"
  ]}
  correctAnswer={1}
  explanation="Contrairement à <div> en HTML, <View> ne peut pas contenir de texte directement. Tout texte doit être encapsulé dans <Text>. L'erreur affichée est : 'Text strings must be rendered within a <Text> component'. C'est l'erreur la plus courante quand on passe du web au mobile."
/>

<QuickCheck
  question="7. Pourquoi une image distante ne s'affiche-t-elle pas sans width et height ?"
  options={[
    "React Native affiche une erreur de compilation",
    "L'image est chargée mais a une taille de 0x0 pixels par défaut",
    "React Native ne supporte pas les images distantes",
    "Les dimensions sont automatiquement calculées à partir de l'URL"
  ]}
  correctAnswer={1}
  explanation="React Native ne connaît pas les dimensions d'une image distante avant son chargement. Sans width et height dans le style, l'image a une taille de 0x0 pixels : elle est chargée mais invisible. Les images locales (require) ont leurs dimensions déterminées à partir du fichier."
/>

<QuickCheck
  question="8. Quelle est la différence entre ScrollView et View ?"
  options={[
    "ScrollView est plus rapide que View",
    "View peut afficher du texte, ScrollView ne le peut pas",
    "ScrollView permet le défilement du contenu, View ne le peut pas",
    "ScrollView est uniquement pour les listes, View pour tout le reste"
  ]}
  correctAnswer={2}
  explanation="En React Native, le défilement n'est pas automatique comme dans un navigateur web. View ne permet pas le scroll. ScrollView ajoute la possibilité de faire défiler le contenu. Si votre contenu dépasse la taille de l'écran, il faut utiliser ScrollView (ou FlatList pour les longues listes)."
/>

## StyleSheet et Flexbox

<QuickCheck
  question="9. Pourquoi React Native n'utilise-t-il pas de fichiers CSS ?"
  options={[
    "Le CSS est obsolète",
    "React Native s'exécute sur des composants natifs, pas dans un navigateur avec un moteur CSS",
    "Les fichiers CSS sont trop lourds pour le mobile",
    "React Native utilise le CSS mais sous un autre nom"
  ]}
  correctAnswer={1}
  explanation="React Native ne s'exécute pas dans un navigateur web : il n'y a pas de moteur CSS. Les styles sont des objets JavaScript dans StyleSheet.create() qui sont traduits en propriétés natives de chaque plateforme. Les propriétés sont similaires au CSS (backgroundColor, fontSize) mais pas identiques."
/>

<QuickCheck
  question="10. Quelle est la direction par défaut de Flexbox en React Native ?"
  options={[
    "row (horizontal, comme en CSS web)",
    "column (vertical)",
    "row-reverse",
    "Il n'y a pas de direction par défaut"
  ]}
  correctAnswer={1}
  explanation="En React Native, flexDirection est 'column' par défaut : les éléments s'empilent verticalement. En CSS web, le défaut est 'row' (horizontal). C'est logique pour le mobile où le contenu défile naturellement de haut en bas. Si vous voulez des éléments côte à côte, ajoutez flexDirection: 'row'."
/>

<QuickCheck
  question="11. Comment appliquer conditionnellement un style en React Native ?"
  options={[
    "Avec className et une condition ternaire",
    "Avec un tableau de styles : style={[styles.base, condition && styles.variant]}",
    "Avec la propriété CSS :hover",
    "En modifiant le fichier CSS dynamiquement"
  ]}
  correctAnswer={1}
  explanation="En React Native, on utilise un tableau de styles avec l'opérateur && : style={[styles.base, isActive && styles.active]}. Si la condition est false, le style conditionnel est ignoré. Il n'y a pas de className ni de CSS en React Native."
/>

<QuickCheck
  question="12. Quelle propriété utiliser pour ajouter une ombre sur Android ?"
  options={[
    "box-shadow",
    "shadowColor avec shadowOffset",
    "elevation",
    "shadow"
  ]}
  correctAnswer={2}
  explanation="Sur Android, les ombres sont gérées par la propriété elevation (un nombre entier). Les propriétés shadowColor, shadowOffset, shadowOpacity, shadowRadius sont spécifiques à iOS. Pour un rendu cohérent sur les deux plateformes, il faut définir les deux."
/>

## Navigation

<QuickCheck
  question="13. Comment Expo Router définit-il les routes de l'application ?"
  options={[
    "Avec une configuration dans un fichier routes.js",
    "Par la structure des fichiers dans le dossier app/",
    "Avec des annotations dans le code des composants",
    "Avec le fichier app.json"
  ]}
  correctAnswer={1}
  explanation="Expo Router utilise le routing basé sur les fichiers : chaque fichier dans le dossier app/ correspond automatiquement à une route. Par exemple, app/about.tsx crée la route /about. Pas besoin de configuration manuelle des routes."
/>

<QuickCheck
  question="14. Quelle est la différence entre router.push() et router.replace() ?"
  options={[
    "push est pour le web, replace pour le mobile",
    "push ajoute un écran à la pile (retour possible), replace remplace l'écran actuel (pas de retour)",
    "replace est plus rapide que push",
    "push et replace font exactement la même chose"
  ]}
  correctAnswer={1}
  explanation="router.push() empile un nouvel écran : l'utilisateur peut revenir en arrière avec un swipe ou le bouton retour. router.replace() remplace l'écran actuel sans l'empiler : pas de retour possible. replace est utile après une connexion pour ne pas pouvoir revenir à l'écran de login."
/>

<QuickCheck
  question="15. Comment créer une route dynamique /users/42 avec Expo Router ?"
  options={[
    "En créant un fichier app/users/42.tsx",
    "En créant un fichier app/users/[id].tsx et en utilisant useLocalSearchParams()",
    "En ajoutant un paramètre dans app.json",
    "En utilisant React Router comme en R4A10"
  ]}
  correctAnswer={1}
  explanation="Les crochets dans le nom du fichier indiquent un paramètre dynamique : app/users/[id].tsx correspond à /users/1, /users/42, etc. On récupère le paramètre avec useLocalSearchParams(). C'est l'équivalent de /users/:id avec React Router et useParams() en R4A10."
/>
