## Fonctions

<QuickCheck
  question="4. Quelle est la syntaxe correcte pour une arrow function avec return implicite ?"
  options={[
    "const add = (a, b) => a + b",
    "const add = (a, b) => { a + b }",
    "const add = (a, b) -> a + b",
    "const add = function(a, b) => a + b"
  ]}
  correctAnswer={0}
  explanation=" Sans accolades, le return est implicite : (a, b) => a + b retourne automatiquement.Avec accolades { a + b }, il faut return explicite sinon retourne undefined.La syntaxe -> n'existe pas en JavaScript (c'est du PHP/Kotlin).On ne peut pas mélanger function et => dans la même déclaration. Règle : pas d'accolades = return implicite."
/>

<QuickCheck
  question="5. Comment retourner un objet avec une arrow function et return implicite ?"
  options={[
    "const makeUser = (name) => ({ name })",
    "const makeUser = (name) => { name }",
    "const makeUser = (name) => name",
    "const makeUser = (name) => [name]"
  ]}
  correctAnswer={0}
  explanation=" Pour retourner un objet en return implicite, entourez-le de parenthèses : () => ({ name }).Sans parenthèses { name }, JavaScript interprète les accolades comme un bloc de code, pas un objet.=> name retourne juste la valeur name, pas un objet.=> [name] retourne un tableau, pas un objet. Les parenthèses forcent l'interprétation comme objet."
/>

## Tableaux

<QuickCheck
  question="6. Quelle méthode utiliser pour transformer chaque élément d'un tableau ?"
  options={[
    ".map()",
    ".filter()",
    ".find()",
    ".forEach()"
  ]}
  correctAnswer={0}
  explanation=" .map() transforme chaque élément et retourne un nouveau tableau de même longueur..filter() sélectionne des éléments (peut avoir moins d'éléments), ne transforme pas..find() retourne UN SEUL élément, pas un tableau..forEach() exécute du code mais ne retourne rien (undefined). Pour transformer : toujours .map() !"
/>

<QuickCheck
  question="7. Que retourne .filter() ?"
  options={[
    "Un nouveau tableau avec les éléments qui passent le test",
    "Le premier élément qui passe le test",
    "true ou false",
    "Le nombre d'éléments qui passent le test"
  ]}
  correctAnswer={0}
  explanation=" .filter() retourne un nouveau tableau avec seulement les éléments où la fonction retourne true..find() retourne LE PREMIER élément qui passe, pas tous..some() retourne true/false (booléen), pas un tableau..reduce() pourrait compter les éléments mais ce n'est pas son usage principal. .filter() = garder certains éléments."
/>

<QuickCheck
  question="8. Que fait .reduce() ?"
  options={[
    "Réduit un tableau à une seule valeur (ex: somme)",
    "Réduit la taille d'un tableau",
    "Supprime les doublons",
    "Filtre les valeurs nulles"
  ]}
  correctAnswer={0}
  explanation=" .reduce() accumule les valeurs pour les réduire à UNE SEULE valeur (somme, produit, objet, etc.).Il ne réduit pas la taille du tableau (c'est .filter() ou .slice()).Pour les doublons, utilisez Set ou .filter() avec indexOf.Pour filtrer les nulls, utilisez .filter(). .reduce() = accumuler vers une valeur unique."
/>

    "Object.getKeys(obj)",
    "obj.getKeys()"
  ]}

Autres méthodes utiles : Object.values() et Object.entries()."

## Destructuration

<QuickCheck
  question="10. Que fait ce code : const { name, age } = user ?"
  options={[
    "Extrait name et age de l'objet user",
    "Crée un nouvel objet avec name et age",
    "Compare name et age dans user",
    "Fusionne name et age dans user"
  ]}
  correctAnswer={0}
  explanation=" C'est la destructuration : elle extrait les propriétés name et age de user dans des variables séparées.Elle n'écrit pas, elle lit et extrait.Elle ne crée pas un nouvel objet, elle crée des variables.Elle n'est pas une comparaison (pas de ==).Elle ne fusionne rien. Destructuration = extraire des propriétés en variables."
/>

<QuickCheck
  question="11. Comment renommer une variable lors de la destructuration ?"
  options={[
    "const { name: userName } = user",
    "const { name as userName } = user",
    "const { name -> userName } = user",
    "const { userName = name } = user"
  ]}
  correctAnswer={0}
  explanation=" La syntaxe correcte est { name: userName } - deux-points pour renommer.'as' n'est pas utilisé en JavaScript (c'est du TypeScript pour le casting).La flèche -> n'est pas la syntaxe JavaScript.{ userName = name } crée une valeur par défaut, ne renomme pas. Pensez-y comme 'nom d'origine : nouveau nom'."
/>

## Spread Operator

<QuickCheck
  question="12. Que fait le spread operator avec un tableau ?"
  options={[
    "Déploie les éléments d'un tableau",
    "Supprime les doublons",
    "Inverse l'ordre des éléments",
    "Trie le tableau"
  ]}
  correctAnswer={0}
  explanation=" Le spread (...) déploie/étale les éléments : [1, 2, ...arr] ajoute tous les éléments de arr.Il ne supprime pas les doublons (utilisez new Set([...arr])).Il ne tri pas et n'inverse pas l'ordre.Il ne trie pas non plus (utilisez .sort()). Le spread = étaler les éléments individuellement."
/>

<QuickCheck
  question="13. Comment copier un objet sans le modifier (immutabilité) ?"
  options={[
    "const copy = { ...original }",
    "const copy = original",
    "const copy = original.copy()",
    "const copy = Object(original)"
  ]}
  correctAnswer={0}
  explanation=" { ...original } crée une copie superficielle (shallow copy) - modifications n'affectent pas l'original.= original fait une référence, pas une copie - modifier l'un modifie l'autre !.copy() n'existe pas sur les objets JavaScript.Object(original) ne copie pas, crée juste un wrapper. Le spread est LA méthode standard pour copier."
/>

## Structures de contrôle

<QuickCheck
  question="14. Que fait l'opérateur ternaire ? condition ? 'oui' : 'non' ?"
  options={[
    "Retourne 'oui' si la condition est vraie, sinon 'non'",
    "Compare deux valeurs",
    "Retourne toujours 'oui'",
    "C'est une erreur de syntaxe"
  ]}
  correctAnswer={0}
  explanation="L'opérateur ternaire est une version condensée de if/else : condition ? valeurSiVrai : valeurSiFaux. Il n'est pas une comparaison, c'est une expression conditionnelle. Il retourne l'une des deux valeurs selon la condition. C'est une syntaxe JavaScript valide et très utilisée. Le ternaire est parfait pour les assignations conditionnelles simples."
/>

## TypeScript

<QuickCheck
  question="15. Quelle est la différence principale entre JavaScript et TypeScript ?"
  options={[
    "TypeScript ajoute des types statiques à JavaScript",
    "TypeScript est plus rapide que JavaScript",
    "TypeScript remplace JavaScript complètement",
    "TypeScript ne fonctionne que dans Node.js"
  ]}
  correctAnswer={0}
  explanation=" TypeScript = JavaScript + types statiques pour détecter les erreurs avant l'exécution.TypeScript n'est PAS plus rapide à l'exécution - il est compilé en JavaScript.Il ne remplace pas JavaScript, il se compile EN JavaScript.Il fonctionne partout où JavaScript fonctionne (navigateur + Node.js). TypeScript = superset de JavaScript."
/>

<QuickCheck
  question="16. Comment typer les paramètres d'une fonction en TypeScript ?"
  options={[
    "function add(a: number, b: number): number",
    "function add(a number, b number) number",
    "function add<number>(a, b): number",
    "function add(a, b): number, number"
  ]}
  correctAnswer={0}
  explanation=" La syntaxe correcte : function add(a: number, b: number): number - deux-points après chaque paramètre et après les parenthèses.Sans deux-points, ce n'est pas du TypeScript valide.<number> est pour les génériques, pas pour typer des paramètres simples.Les types ne vont pas après le return mais après les parenthèses de la fonction."
/>
