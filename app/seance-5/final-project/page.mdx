# Projet Final

Le projet final est votre opportunité de démontrer toutes les compétences acquises durant ce cours.

<Callout type="info" title="Objectif">
Construire une application React complète et fonctionnelle, déployée en production, qui utilise les concepts vus dans les 5 séances.

**Ce projet comptera pour votre évaluation finale.**
</Callout>

## Format du projet

### Modalités

- **Individuel** ou **en binôme** (2 personnes maximum)
- **Duree :** 2 semaines apres la derniere seance

<Callout type="tip" title="Comment travailler efficacement">
- **Commencez par la structure** : Setup Vite + React Router + pages vides
- **Developpez feature par feature** : Une fonctionnalite a la fois
- **Testez regulierement** : Lancez `npm run dev` et verifiez dans le navigateur
- **Committez souvent** : Un commit par fonctionnalite ajoutee
- **Deployez tot** : Deployez sur Vercel des le debut pour detecter les problemes

**Temps estime total :** 8-12 heures sur 2 semaines
</Callout>

### Ce que vous devez rendre

1. **Lien GitHub** - Repository public avec le code source
2. **Lien de deploiement** - Application deployee sur Vercel/Netlify
3. **README.md** - Documentation complete (voir plus bas)

<Callout type="warning">
**Date limite :** A definir par l'enseignant.
</Callout>

## Options de projets

Choisissez **l'un des projets suivants** ou proposez votre propre idée (à faire valider).

### Option 1 : Recipe Manager

Application de gestion de recettes de cuisine.

**Fonctionnalités requises :**
- Ajouter/Modifier/Supprimer des recettes
- Chaque recette contient :
  - Nom, image, temps de préparation
  - Liste d'ingrédients
  - Instructions étape par étape
  - Catégorie (entrée, plat, dessert)
  - Difficulté (facile, moyen, difficile)
- Recherche par nom ou ingrédient
- Filtrage par catégorie et difficulté
- Page de détails pour chaque recette
- Marquer des recettes comme favorites
- Persistance avec localStorage

**Bonus (optionnel) :**
- Calculateur de portions (ajuster les quantités)
- Liste de courses générée depuis une recette
- Notes et commentaires sur les recettes
- Timer de cuisine intégré

### Option 2 : Expense Tracker

Application de suivi de dépenses personnelles.

**Fonctionnalités requises :**
- Ajouter/Modifier/Supprimer des dépenses
- Chaque dépense contient :
  - Montant, date, catégorie
  - Description
  - Type (dépense ou revenu)
- Catégories prédéfinies (alimentation, transport, loisirs, etc.)
- Vue par liste et par mois
- Statistiques :
  - Total des dépenses du mois
  - Répartition par catégorie (avec graphique simple)
  - Budget restant si défini
- Filtrage par catégorie et période
- Persistance avec localStorage

**Bonus (optionnel) :**
- Graphiques avec une bibliothèque (Chart.js, Recharts)
- Définir un budget mensuel par catégorie
- Alertes si budget dépassé
- Export des données en CSV

### Option 3 : Workout Logger

Application de suivi d'entraînements sportifs.

**Fonctionnalités requises :**
- Ajouter/Modifier/Supprimer des séances d'entraînement
- Chaque séance contient :
  - Date, durée, type (cardio, musculation, yoga, etc.)
  - Exercices réalisés
  - Notes/ressenti
- Créer et sauvegarder des routines d'entraînement
- Calendrier des séances (vue liste ou grille)
- Statistiques :
  - Nombre de séances par semaine/mois
  - Temps total d'entraînement
  - Exercices les plus pratiqués
- Filtrage par type d'entraînement
- Persistance avec localStorage

**Bonus (optionnel) :**
- Graphique de progression
- Timer pour les exercices
- Photos avant/après
- Objectifs et suivi de progression

## Exigences techniques

### Obligatoires (requis pour valider le projet)

<Callout type="error" title="Requirements">
Votre projet **DOIT** inclure :

✅ **React et Vite**
- Application créée avec Vite
- Composants fonctionnels (pas de class components)

✅ **State Management**
- useState pour la gestion d'état local
- Minimum 3 états différents

✅ **Side Effects**
- useEffect pour au moins un use case
  - Exemples : localStorage, fetch API, event listeners

✅ **Routing**
- React Router avec minimum 3 pages/routes
  - Exemple : Home, Add/Edit, Detail

✅ **Formulaires**
- Au moins un formulaire avec validation
- Inputs contrôlés (controlled components)
- Gestion des erreurs de validation

✅ **Liste dynamique**
- Affichage de données avec .map()
- Keys uniques sur chaque élément

✅ **Persistance**
- localStorage OU appels API (minimum)

✅ **Responsive Design**
- Fonctionne sur mobile et desktop
- Testable avec DevTools responsive mode

✅ **Déploiement**
- Application déployée sur Vercel ou Netlify
- Lien public fonctionnel

✅ **Code propre**
- Pas d'erreurs dans la console
- Code indenté et lisible
- Conventions de nommage respectées
</Callout>

### Recommandées (pour un meilleur score)

<Callout type="tip" title="Bonnes pratiques">
Pour obtenir une excellente note, ajoutez :

⭐ **Custom Hooks**
- Au moins un custom hook réutilisable

⭐ **Composition de composants**
- Composants petits et réutilisables
- Props bien structurées

⭐ **Gestion d'erreur**
- États de chargement (loading states)
- Messages d'erreur clairs
- Cas limites gérés (listes vides, etc.)

⭐ **UX/UI**
- Interface intuitive et agréable
- Feedback visuel (confirmations, animations)
- Navigation fluide

⭐ **Performance**
- Pas de re-renders inutiles
- Code optimisé

⭐ **Documentation**
- README complet et clair
- Commentaires pour le code complexe
- Instructions de setup détaillées
</Callout>

## Questions fréquentes

**Q : Puis-je utiliser des bibliothèques CSS comme Tailwind ?**
R : Oui, absolument ! Tailwind, Bootstrap, ou CSS pur sont tous acceptés.

**Q : Puis-je utiliser une API externe ?**
R : Oui, mais ce n'est pas obligatoire. localStorage suffit pour la persistance.

**Q : Puis-je réutiliser du code du projet guidé ?**
R : Vous pouvez vous inspirer de la structure, mais votre projet doit être différent.

**Q : Combien de temps ça prend ?**
R : En moyenne 8-12 heures pour un projet de qualité. Répartissez sur les 2 semaines.

**Q : Puis-je changer de projet en cours de route ?**
R : Non, choisissez bien dès le début pour éviter de perdre du temps.

**Q : L'application doit-elle avoir un backend ?**
R : Non, localStorage est suffisant. Un backend est un bonus mais pas requis.

**Q : Que faire si je bloque ?**
R :
1. Consultez la documentation React
2. Demandez à l'IA (ChatGPT, Claude)
3. Cherchez sur Stack Overflow
4. Envoyez un email à l'enseignant
