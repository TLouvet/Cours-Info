# Pratiques React

Maintenant que vous connaissez les bases de React, apprenons a ecrire du code de qualite.

<Callout type="info">
**Le code est lu beaucoup plus souvent qu'il n'est ecrit.**

Un bon code n'est pas seulement un code qui fonctionne, c'est un code que vous (et d'autres) pourrez comprendre et maintenir dans 6 mois.
</Callout>

## Principes de design de composants

### Single Responsibility Principle

Un composant doit avoir **une seule responsabilite**, une seule raison de changer.

**Mauvais exemple :** Un composant qui fait tout

```jsx
// ❌ Ce composant gere users, products, orders et stats
function Dashboard() {
  const [users, setUsers] = useState([]);
  const [products, setProducts] = useState([]);
  const [orders, setOrders] = useState([]);
  const [stats, setStats] = useState({});

  // 200 lignes de code...

  return (
    <div>
      {/* Header, User list, Product list, Order list, Statistics, Charts */}
    </div>
  );
}
```

**Bon exemple :** Composants decomposes

```jsx
// ✅ Chaque composant a une seule responsabilite
function Dashboard() {
  return (
    <div>
      <DashboardHeader />
      <StatsCards />
      <UsersList />
      <ProductsList />
      <OrdersList />
      <SalesChart />
    </div>
  );
}

function UsersList() {
  const [users, setUsers] = useState([]);
  // Logique specifique aux users
  return <div>{/* Affichage users */}</div>;
}

function StatsCards() {
  const [stats, setStats] = useState({});
  // Logique specifique aux stats
  return <div>{/* Affichage stats */}</div>;
}
```

### Quand diviser un composant

Divisez un composant quand :

1. **Il depasse 150 lignes** - Trop long = trop complexe

2. **Logique reutilisable ailleurs**
   ```jsx
   // Si vous utilisez <Button> partout, extrayez-le
   function Button({ children, onClick, variant = 'primary' }) {
     return (
       <button className={`btn btn-${variant}`} onClick={onClick}>
         {children}
       </button>
     );
   }
   ```

3. **Separation des responsabilites claire**
   ```jsx
   // Separez le formulaire de la liste
   function UsersPage() {
     return (
       <>
         <AddUserForm />
         <UsersList />
       </>
     );
   }
   ```

## Conventions de nommage

### Composants : PascalCase

```jsx
// ✅ Bon
function UserCard() { }
function ProductList() { }
function NavigationBar() { }

// ❌ Mauvais
function userCard() { }
function product_list() { }
```

### Fonctions et variables : camelCase

```jsx
// ✅ Bon
const userName = 'Alice';
const isLoggedIn = true;
function fetchUserData() { }
function handleSubmit() { }

// ❌ Mauvais
const UserName = 'Alice';
const is_logged_in = true;
```

### Event handlers : handle* ou on*

```jsx
// ✅ handle* dans le composant
function Form() {
  const handleSubmit = (e) => {
    e.preventDefault();
  };

  const handleInputChange = (e) => {
    // ...
  };

  return <form onSubmit={handleSubmit}>...</form>;
}

// ✅ on* pour les props
function Button({ onButtonClick, children }) {
  return <button onClick={onButtonClick}>{children}</button>;
}
```

### Props booleennes : is*, has*, can*, should*

```jsx
// ✅ Bon
<Button isLoading={true} />
<User hasPermission={true} />
<Form canSubmit={false} />
<Modal shouldShow={true} />

// ❌ Mauvais - pas clair
<Button loading={true} />
<User permission={true} />
```

## Gestion des Props

### Destructuration

**Toujours destructurer les props :**

```jsx
// ✅ Bon
function UserCard({ name, email, avatar, isActive }) {
  return (
    <div>
      <img src={avatar} alt={name} />
      <h3>{name}</h3>
      <p>{email}</p>
      {isActive && <span>En ligne</span>}
    </div>
  );
}

// ❌ Mauvais - repetitif et moins lisible
function UserCard(props) {
  return (
    <div>
      <img src={props.avatar} alt={props.name} />
      <h3>{props.name}</h3>
      <p>{props.email}</p>
      {props.isActive && <span>En ligne</span>}
    </div>
  );
}
```

### Valeurs par defaut

```jsx
// ✅ Valeurs par defaut dans la destructuration
function Button({
  children,
  variant = 'primary',
  size = 'medium',
  disabled = false
}) {
  return (
    <button className={`btn-${variant} btn-${size}`} disabled={disabled}>
      {children}
    </button>
  );
}

// Utilisation
<Button>Click</Button> // Utilise les valeurs par defaut
<Button variant="secondary" size="large">Big Button</Button>
```

## Gestion de l'etat

### Principe : Start local, lift when needed

**Commencez avec l'etat local, montez-le seulement quand necessaire.**

```jsx
// ✅ Etat local si utilise seulement ici
function SearchBar() {
  const [query, setQuery] = useState('');
  return <input value={query} onChange={e => setQuery(e.target.value)} />;
}

// ✅ Lift state up quand plusieurs composants en ont besoin
function ProductsPage() {
  const [searchQuery, setSearchQuery] = useState('');

  return (
    <>
      <SearchBar query={searchQuery} onQueryChange={setSearchQuery} />
      <ProductList query={searchQuery} />
    </>
  );
}
```

### Ne pas tout mettre dans l'etat

**Les valeurs derivees ne doivent PAS etre dans l'etat.**

```jsx
// ❌ Mauvais : Etat redondant
function ProductList() {
  const [products, setProducts] = useState([]);
  const [productCount, setProductCount] = useState(0); // ❌ Redondant !
  const [expensiveProducts, setExpensiveProducts] = useState([]); // ❌ Redondant !

  useEffect(() => {
    setProductCount(products.length); // ❌ Pas necessaire
    setExpensiveProducts(products.filter(p => p.price > 100)); // ❌ Pas necessaire
  }, [products]);
}

// ✅ Bon : Calculer a la volee
function ProductList() {
  const [products, setProducts] = useState([]);

  // ✅ Calcule, pas stocke
  const productCount = products.length;
  const expensiveProducts = products.filter(p => p.price > 100);

  return (
    <div>
      <p>Total : {productCount} produits</p>
      <p>Chers : {expensiveProducts.length}</p>
    </div>
  );
}
```

<Callout type="tip">
**Regle :** Si vous pouvez calculer une valeur a partir de l'etat existant, ne la mettez pas dans l'etat.
</Callout>

### Immutabilite de l'etat

**Ne JAMAIS muter l'etat directement.**

```jsx
// ❌ Mutation directe - React ne detecte PAS le changement
const addProduct = (newProduct) => {
  products.push(newProduct); // ❌ Mutation !
  setProducts(products); // Meme reference, pas de re-render
};

// ✅ Creer de nouveaux objets/tableaux
const addProduct = (newProduct) => {
  setProducts([...products, newProduct]); // Nouvelle reference
};

// ✅ Modifier un element
const updateProduct = (id, newPrice) => {
  setProducts(products.map(p =>
    p.id === id ? { ...p, price: newPrice } : p
  ));
};

// ✅ Supprimer un element
const removeProduct = (id) => {
  setProducts(products.filter(p => p.id !== id));
};
```

<QuickCheck
  question="Pourquoi ne faut-il JAMAIS muter l'etat directement ?"
  options={[

    "C'est interdit en JavaScript",
    "React ne detecte pas les changements, donc pas de re-render",
    "Ca ralentit l'application"

  explanation="React compare les references d'objets/tableaux. Si vous mutez directement (users.push()), la reference reste la meme, React ne detecte PAS le changement et ne re-render pas. Toujours creer de nouveaux objets/tableaux : setUsers([...users, newUser])."

## Composition over Complexity

Preferez composer plusieurs composants qu'un composant avec beaucoup de props conditionnelles.

**Trop de props conditionnelles :**

```jsx
// ❌ Trop de conditions dans un seul composant
function Card({ title, content, hasImage, imageUrl, hasButton, buttonText, onButtonClick }) {
  return (
    <div className="card">
      <h3>{title}</h3>
      {hasImage && <img src={imageUrl} />}
      <p>{content}</p>
      {hasButton && <button onClick={onButtonClick}>{buttonText}</button>}
    </div>
  );
}
```

**Composition :**

```jsx
// ✅ Composants composables
function Card({ children }) {
  return <div className="card">{children}</div>;
}

function CardTitle({ children }) {
  return <h3>{children}</h3>;
}

function CardContent({ children }) {
  return <p>{children}</p>;
}

// Utilisation flexible
<Card>
  <CardTitle>Hello</CardTitle>
  <CardImage src="/img.jpg" alt="Hello" />
  <CardContent>World</CardContent>
  <Button onClick={handler}>Click</Button>
</Card>
```

## Organisation du code dans un composant

**Ordre recommande :**

```jsx
function MyComponent({ propA, propB }) {
  // 1. Hooks d'etat
  const [state1, setState1] = useState(initialValue);

  // 2. Hooks d'effet
  useEffect(() => {
    // Side effect
  }, [dependencies]);

  // 3. Custom hooks
  const { data, loading } = useFetch('/api/data');

  // 4. Variables derivees
  const computedValue = state1 + state2;

  // 5. Event handlers
  const handleClick = () => {
    setState1(newValue);
  };

  // 6. Retours anticipes (loading, error)
  if (loading) return <Spinner />;
  if (error) return <Error />;

  // 7. Return principal
  return (
    <div>
      {/* ... */}
    </div>
  );
}
```

## Extraire les constantes

**Ne definissez pas de magic numbers dans le rendu.**

```jsx
// ❌ Magic numbers dans le JSX
function ProductCard({ product }) {
  return (
    <div>
      <h3>{product.name}</h3>
      {product.price > 100 && <span className="expensive">Cher !</span>}
      {product.stock < 5 && <span className="low-stock">Stock bas</span>}
    </div>
  );
}

// ✅ Constantes nommees en haut du fichier
const EXPENSIVE_THRESHOLD = 100;
const LOW_STOCK_THRESHOLD = 5;

function ProductCard({ product }) {
  const isExpensive = product.price > EXPENSIVE_THRESHOLD;
  const isLowStock = product.stock < LOW_STOCK_THRESHOLD;

  return (
    <div>
      <h3>{product.name}</h3>
      {isExpensive && <span className="expensive">Cher !</span>}
      {isLowStock && <span className="low-stock">Stock bas</span>}
    </div>
  );
}
```

## Recapitulatif

<Callout type="success" title="Checklist des pratiques">
**Composants**
- Un composant = une responsabilite
- Max 150 lignes
- Noms en PascalCase

**Props**
- Toujours destructurer
- Valeurs par defaut
- Noms clairs (is*, has*, on*, handle*)

**Etat**
- Commencer local
- Pas de valeurs derivees dans l'etat
- Jamais de mutation directe

**Code**
- DRY (Don't Repeat Yourself)
- Composition plutot que props conditionnelles
- Constantes extraites
- Organisation claire dans le composant
</Callout>
